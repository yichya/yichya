# Music

过去一年买了三款耳机和一个 MP3，放一起好了

## Redmi Buds 7S

去年的 [Gadgets (2025)](../gadgets-2025) 里面就提过想买，一方面还是对降噪还是有点需求（主要是想着骑车下班路上听一点鉴证内容），当然也有一些原因是去年买的那个 99 块钱的功能缺失确实有点多而且连接不太稳定。原价 199，蹲了一阵儿 169 左右入手

![](../assets/images/gadgets-2026/redmi_buds_7s.jpg)

实际体验下来：

* 音量很小，就算在办公室这种并不怎么吵闹的地方也要顶在 HyperOS 默认音量限制的上限听
* 降噪拉完了，周围噪音稍微大一点的时候就会自己莫名其妙的关掉，连比如骑车、飞机、地铁之类的最常见的情况都搞不定；结合上面音量小的问题，结果就是下班路上根本什么也听不清
* 音质调的也不是很好（感觉跟 AirPods 4 那种两头翘的曲线刚好反过来），甚至应该说远远不如去年买的那个 99 块的，结果就导致光拿来听歌也几乎没法用。下面是用 HyperOS 自带的个性化听感调出来的一个曲线，也就是说需要叠一个两头翘的 EQ 才比较顺耳

![](../assets/images/gadgets-2026/curve.jpeg)

总之又是比较踩坑的一次，虽然这个价格摆在这里吧也不好说太多

## Echo Nano

之前零零散散买了好几个 MP3 都或多或少有点不满意，这次难得见到一个传统形态的新产品，于是果断入手

![](../assets/images/gadgets-2026/echo_nano.jpeg)

顺便做了一个一直想做的事情：用 AI 把 iPod Shuffle 里面的歌提取了一遍（[AI 真好用](https://github.com/yichya/itunesdb_parser)）。粗略用下来：

* 质感不错，比较可惜的是自带存储约等于没有，还得塞个 TF 卡，但是 TF 卡又跟很多类似设备一样会冒个尖尖出来
* 音质还行吧，虽然有很多项目可以调，什么陡降缓降啥的，但听着也没听出啥区别
* 随机播放也是一坨，后退、前进的顺序还是会乱
  * 往回退一首歌可以，多退一首就不知道跑到哪儿去了；此时切下一首也一样会完全随机
  * 甚至不知道会在哪些时候触发这个 shuffle 的操作，咱就是不知道这个东西到底难做在哪
* 更新了一次固件之后 FAT32 直接炸了，不过换成 ExFAT 之后少了很多小毛病
  * 但是又比较难绷的是内置存储如果要升级固件的话必须还得是 FAT32；固件升级倒是还挺积极的，买来一个来月推了两次

顺便还发现一个事情是之前买的 iriver 太久没用，结果电池鼓包把后盖都撑开胶了 = = 真的是超级无敌辣鸡

## 小米 BE6500 Pro（基本实锤是缩水版）

家里小米的开关什么的比较多所以买了中枢网关，但之前跟老 NETGEAR 路由器一块儿都扔在次卧，一大堆线乱成一团；后面看见这款无线路由器自带中枢，一直很心动。刚好去年夏天爹妈回家长住，把老路由器直接寄回去，然后就跑了一趟楼下的小米之家。本来看生产日期 2025.2 应该不是缩水版，于是激情下单，店员给了一个券儿之后 549 到手；后面又发现[这里](https://www.acwifi.net/31949.html)缩水版的包装和草民买到的一样，光凭包装也不太能完全确定，但好在里面还提供了两个重量数据，于是草民一称，1.6KG……那没救了。下图来自 [acwifi](https://www.acwifi.net/27123.html)，缩水版会略有不同仅供参考

![](../assets/images/gadgets-2026/be6500.jpg)

买来之后发现最大的坑：太高，刚好塞不进电视柜下面（差了大概不到 1cm），只好跟之前的 NETGEAR 一样先放在次卧

这玩意儿的 2.4GHz 确实是不怎么样（这还是缩水版据说优化了之后的结果，那没优化的得有多烂啊 = =），扔在次卧就导致其他房间的几个 2.4GHz 连接的灯经常断开连接，主卧的显示器挂灯尤其严重，颇令人头疼；5GHz 倒是没啥毛病，比之前的 NETGEAR 好不少。买了 12V 拆分线之后腾出来一个插座，就扔电视后面了，没想到效果意外的好，几个灯的连接问题轻松解决，最远的次卧吸顶灯也有 -70dB 左右，完全够用。顺便还优化了 NAS 跟 Volterra 的通信，当然这个也有点复杂，涉及到 multicast DNS 的一大堆坑，之后找时间细讲

用了差不多一年，总体感觉还是挺好的。自带中枢网关很方便，那部分也可以跟系统固件本身分开更新，功能上大致也没什么问题。至于缩水版砍了散热之类的影响，印象中刚买来的时候貌似是有过一次死机，但后面设置了每天定时重启 + 升级过一两次固件之后就没再出过什么问题，也经历了一年最热最冷的时间段，所以评价为确实没啥大毛病。至于推不推荐，按说买新不买旧，但是 BE7200 Pro 提升不大贵快一倍，BE10000 Pro 更是完全买不起；BE6500 Pro 现在倒是四百出头，但是缩水这事儿……膈应的话还是买个普通一点的搭配中枢网关吧

## USB A - C 转换头

上面那个 Logi Bolt Type-C 接收器直接插在 NUC 的 Type-C 口上，会在事件查看器里面莫名其妙的看见一大堆可修正错误，然后有的时候修正着修正着就修不正了，鼠标就没反应了。用耳机的转接头转一下插在 A 口上就不会有问题，所以买了个这个顶上

![](../assets/images/gadgets-2026/ac.jpg)

后来发现是 [ASPM](https://en.wikipedia.org/wiki/Active_State_Power_Management) 的问题。Skull Canyon 的 Type-C 接口是雷电 3，被 PCI-E 相关的东西管着倒是也很合理（包括 UEFI 里面需要设置启动时初始化 ThunderBolt 3 控制器相关的两个选项，才能在 UEFI 设置里面用鼠标），关了之后一切恢复了正常。感觉 ASPM 这玩意儿好像除了捣乱之外啥用也没有，要么断联要么降速的。这个转接头倒是还可以给 CanoKey Canary 用，所以也不亏

## 转速计

i160 的水冷系统工作不正常有些日子了，体现为 iCUE 上显示的 CPU 那一侧水冷液的温度会在一瞬间从三四十度窜到六十多度，但与此同时 CPU 温度并没有什么变化，还是维持在大概四五十度的状态；这个状态有时候持续可能几十秒，有时候可能连着半个多小时都不恢复

它回报的水泵转速也持续降低了，于是想确认一下是真的转速降低了还是回报的数据有问题，为此又买了转速计观察顶部风扇转速（这俩从观察的结果来看，几乎可以肯定正相关

![](../assets/images/gadgets-2026/spin.jpg)

但是这玩意儿最终也没用上

* iCUE 回报的转速比转速计测出来的快差不多 5%，还不太稳定，根本就没法用来参考
* 现在那套水冷系统也很难弄回到比较正常的状态上了，虽然从 CPU 的监测来看，用起来倒是还没啥问题

不过有一个很奇怪的发现是 CPU 冷却液温度竟然是和前面板 LED 灯亮度联动的 = = 跑了一小会儿 Prime95 确定散热没问题，那再抽风就临时调低亮度到 66%，后来发现 66% 也不一定行就干脆固定到 33% 了，反正也没必要搞那么亮

所以这个只能留着以后再折腾了。现在硬件价格也是高位中的高位，近期也不太会考虑换平台（AI 还是坑啊

## Pocket Term 35

之前买的 uConsole 是在 Compute Module 的基础上做扩展，直接放原版树莓派进去的这个形态的产品等了这么久才出来一个，而且价格还相当贵，算上之前买来就一直吃灰的 Pi 4 和 TF 卡的价格能上千了（AI 全责

![](../assets/images/gadgets-2026/35.webp)

发货也贼慢，四月底下单等到五月下旬才收到，不过感觉确实还不错，吃灰的 Pi 4 可以拿出来再发挥点作用了。简单体验：

* 适配比 uConsole 靠谱多了，不需要魔改内核，只需要在原版系统的基础上叠几个 Device Tree 的 Overlay 配置一下
  * 它的硬件设计就很好，屏幕走 HDMI，键盘走 Type-C 接口的 USB Host，触摸屏是从 Pi 主板反面用顶针怼上去的
  * Overlay 只需要配置两个，一个是官方系统自带的 Type-C USB Host，另一个是这个产品提供的 I2C 触摸屏
  * 也试了一下非官方的 Ubuntu Server + MATE，键盘正常，触摸屏出不来。其实触摸屏也走 USB 的话会更好
* 键盘一般般，灵敏还算灵敏，但是按键手感不咋样，而且没有背光，默认布局也是一坨
  * 这个键盘是 CircuitPython 实现的（硬件方案不太清楚），布局完全是用 MicroPython 定义的，确实也可以自己魔改
* 官方系统对触摸屏的适配一般，Wayland 下面的 Chromium 不能滚动，戳屏幕偶尔会进入只能移动指针不能触发点击的情况
  * 然后这个键盘的 L R A B X Y 这几个键在默认布局下又真的只是用来输入这几个字母的，纯粹为 RetroPie 设计的
  * 感觉这一点上 uConsole 选择的轨迹球方案确实比触摸屏方案要好一些，小尺寸适配和兼容性都更靠谱
* Pi 的功耗和发热对于一个移动设备来说确实还是太高，而且几乎没有什么电源管理的能力，就算 5000 mAh 的电池也顶不住多久
  * uConsole 的功耗也好不到哪里去，但是电池选择了 18650 的标准方案，比这款的软包电池确实也要靠谱一些
* 从扩展的角度来讲 uConsole 给了 4G 模块，这款如果是用 Pi 4 的话没有什么靠谱方案，Pi 5 还可以从 PCI-E 上想想办法
  * 对于移动设备来说其实还挺有意义的，能把这个问题解决的话基本可以说除了功耗之外会是个相当不错的移动终端

总之用下来的评价是如果手里有吃灰的 Pi 4 / 5 想利用一下的话买一个玩玩也行，但是现在 Pi 的价格贵上天，专门买一套不值
